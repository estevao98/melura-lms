# Services, Workers, And Scheduler

Melura LMS runs inside a Frappe bench and depends on the services expected by
that bench. This document explains what to validate without assuming one
specific production process manager.

## Redis Assumptions

Frappe bench commonly uses separate Redis services for:

- cache;
- queue;
- socketio.

Production Redis should be reachable by the Frappe site but not exposed
publicly. Redis outages must not bypass permissions. Student access and
protected content must continue to require backend checks.

## Development With `bench start`

In local development, this is commonly enough:

```bash
bench start
```

`bench start` is a development convenience. Production should use supervised
processes instead of relying on an interactive shell.

## Production Process Manager Expectations

Production should supervise:

- web process;
- workers;
- scheduler;
- socketio when required;
- Redis services;
- database;
- reverse proxy.

The actual manager may be supervisor, systemd, a provider-managed service, or
the process setup generated by the selected bench deployment method.

## Workers

Workers process background jobs. Validate:

- expected worker queues are running;
- failed jobs are reviewed;
- worker logs do not contain secrets or full sensitive payloads;
- WhatsApp jobs, if added later, keep provider calls backend-side or protected;
- background jobs do not trust frontend-provided student, course, or batch
  scope.

## Scheduler

Scheduler controls scheduled jobs. Validate:

- scheduler status is known;
- it is enabled only when intended;
- scheduled jobs are idempotent where possible;
- future WhatsApp reminders or access sync jobs are permission-safe and
  secret-safe.

## Common Symptoms When Redis Is Down

Symptoms may include:

- pages loading slowly or failing intermittently;
- cache reads returning empty values;
- background jobs not enqueueing or processing;
- socketio connection errors;
- repeated Redis connection errors in logs;
- stale settings not clearing after `clear-cache`.

Redis failure should not cause protected student content to be returned without
authorization.

## Validate Services

Use commands appropriate to the environment:

```bash
bench --site <site> doctor
bench --site <site> scheduler status
bench --site <site> show-pending-jobs
bench --site <site> clear-cache
```

Inspect process status with the production manager in use:

```bash
systemctl status <service-name>
supervisorctl status
ps aux | grep <process-name>
```

Use placeholders in documentation. Do not commit real service names if they
reveal private infrastructure details.
